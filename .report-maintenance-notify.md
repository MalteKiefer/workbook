# Report: maintenance-notify feature

## Summary

This feature makes the cross-customer overdue-systems count live. A new background
thread scheduler recomputes `list_overdue_systems` every fifteen minutes, the same
interval already used by the existing auto-backup and auto-update-check schedulers.
The result feeds two places: the tray icon tooltip (composed together with the
existing update-available tooltip so neither condition clobbers the other) and a new
`maintenance-check-completed` event that every open window's frontend listens for.
The Dashboard nav link in the sidebar now shows a small red dot badge whenever the
overdue count is greater than zero, mirroring the badge pattern already used for the
Einstellungen nav link and for individual overdue systems in the system list view.

## Files created

* `src/lib/maintenanceCheck.ts`: subscribes to the `maintenance-check-completed`
  event, mirroring `updateCheck.ts`'s `listenForUpdateCheckCompleted`.

## Files modified

* `src-tauri/src/lib.rs`: added `AppState.overdue_systems_count` (a `Mutex<usize>`,
  initialized to zero and never persisted to `config.toml`), added
  `MAINTENANCE_CHECK_INTERVAL`, `spawn_maintenance_check_scheduler`, and
  `run_maintenance_check`, and called the new scheduler from `.setup()` right after
  the existing two schedulers. Added `Emitter` to the file's `tauri` import.
* `src-tauri/src/tray.rs`: removed `sync_update_indicator` and replaced it with
  `sync_tray_tooltip`, which reads both the update-available version and the overdue
  count from `AppState` and composes one tooltip string through a new pure helper,
  `compose_tooltip`. Added `Manager` to the file's `tauri` import. Added five unit
  tests for `compose_tooltip`, covering neither condition, only an available update,
  only overdue systems in the singular and plural, and both conditions together.
* `src-tauri/src/updater.rs`: changed the one call site in
  `apply_update_check_result` from
  `tray::sync_update_indicator(app, available_version.as_deref())` to
  `tray::sync_tray_tooltip(app)`.
* `src/state/appStore.ts`: added `overdueSystemCount` (initial value zero) and
  `setOverdueSystemCount`, matching the existing `updateAvailableVersion` and
  `setUpdateAvailableVersion` pair exactly.
* `src/App.tsx`: added a second effect that seeds `overdueSystemCount` from
  `invoke("list_overdue_systems")` on mount and subscribes to
  `listenForMaintenanceCheckCompleted`. Added a badge to the Dashboard nav link,
  copied from the existing Einstellungen badge but using `var(--danger)` instead of
  `var(--accent)`, shown only when `overdueSystemCount > 0`.

## Deviations from the brief, with reasoning

* Extracted the tooltip string composition into a standalone pure function,
  `compose_tooltip`, inside `tray.rs`, instead of inlining that logic directly in
  `sync_tray_tooltip`. The brief left this as a judgment call and offered the
  extraction as the preferred option when it is a clean fit. It was clean here:
  `compose_tooltip` takes only an `Option<&str>` and a `usize` and returns a
  `String`, with no need to touch the tray icon or app state, so it could get five
  direct unit tests instead of relying on a harder to arrange integration style test
  through a live tray icon.
* In `App.tsx`, the initial seed call is typed as `invoke<unknown[]>` rather than
  importing or redeclaring `OverdueSystemDto`. The brief explicitly allowed no
  explicit shape at all when only `.length` is needed, which is the only field this
  effect reads.
* Grouped the `lib.rs`, `tray.rs`, and `updater.rs` backend edits into one commit
  rather than three, since they form a single change that only compiles as a whole:
  the scheduler depends on the new `sync_tray_tooltip` signature, and the
  `updater.rs` call site update is required by that same rename. The frontend change
  is its own commit, and the formatting fix is a third.
