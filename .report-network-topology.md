## Post-review hardening (follow-up commit)

An independent review of `ac1ee7c` approved the feature (build/lint/cargo
test clean, CIDR math verified correct by execution) but flagged a few
cheap low-severity hardening opportunities, all fixed in the follow-up
commit on this branch:

- `src/lib/cidr.ts`: `cidrContains` split a CIDR on `/` without validating
  the prefix half looked like an actual 1-2 digit number before calling
  `Number()` on it. A malformed CIDR with a trailing slash and empty
  prefix (`"10.0.0.0/"`) split into `["10.0.0.0", ""]`, and `Number("")`
  is `0`, so it was silently treated as `/0` and matched every IP -- the
  worst possible failure mode for a function whose own doc comment
  promises `false` for malformed input. Fixed by requiring
  `/^\d{1,2}$/.test(prefixStr.trim())` before converting.
- `src/lib/cidr.ts`: `ipToInt` had the same root cause -- splitting on `.`
  without validating each part looked like digits first, so a
  trailing-empty-octet address like `"1.2.3."` split into 4 parts
  (`["1","2","3",""]`) and silently parsed as `1.2.3.0` instead of being
  rejected. Fixed by requiring each part to match `/^\d{1,3}$/` before
  converting.
- `src/components/NetworkTopologyView.tsx`: a network whose `location_id`
  pointed at a location id absent from the fetched `locations` list would
  silently vanish from the view entirely (not even shown under "Ohne
  Standort"), since the grouping loop only checked `location_id === null`.
  Currently unreachable in practice (the UI never lets a network's
  location be set outside the current customer, and the schema's
  `ON DELETE SET NULL` means a deleted location can't leave a dangling
  id), but cheap to harden defensively. Fixed by also checking
  `location_id` against a `Set` of known location ids and falling back to
  the unassigned bucket when it doesn't match.
- Three nits in the same file, all fixed: removed the sole `systems!`
  non-null assertion in `src/` (replaced with a `const allSystems =
  systems;` binding right after the existing null-guard, which TypeScript
  narrows to non-null on its own); removed the unused `customer_id` field
  from the local `Location` interface (the comment above it already
  claimed it only declared fields the view needs); and de-duplicated the
  double `systemsInNetwork(network)` call per network per render into a
  single `systemsByNetworkId` map built once and read by both the
  `matchedSystemIds` computation and `renderNetwork`.

`npm run build` and `npm run lint` both re-ran clean (exit 0) after these
changes. `src/lib/cidr.test.ts` still does not exist in this project (no
test runner -- see "Test runner check" above), so no test file was added
or updated, per the review's own instruction to skip that unless the file
already existed.
