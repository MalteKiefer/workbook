An independent reviewer approved the actual behavior of all three commits above (all five of their verification commands passed, no dangling references, backward compatibility confirmed) but flagged two issues, both now addressed:

4. `24c251124d0071fb276b2b493be64344106eaf81` — fix(network-scan): make sort-order test exercise the real sort function
   - The test added in commit 1 (`scan_range_results_sort_numerically_not_lexicographically`) built its own `Vec<HostScanResult>` and ran its own inline copy of the `sort_by_key` expression on it, rather than calling `scan_range` or any shared production code. That meant the test only proved that `Ipv4Addr`'s `Ord` implementation sorts numerically, a guarantee of the standard library, not a property this codebase could regress. If `scan_range`'s sort were reverted to the old lexicographic `sort_by(|a, b| a.ip.cmp(&b.ip))`, this test would still pass and catch nothing.
   - Fix: extracted the sort into a standalone `sort_by_ip(results: &mut [HostScanResult])` function placed just above `scan_range` in `src-tauri/src/network_scan.rs`. `scan_range` now calls `sort_by_ip(&mut results)` instead of sorting inline, and the test was updated to call the same `sort_by_ip(&mut results)` instead of duplicating the sort expression. The test's data and assertions were left exactly as they were.
   - Sanity check performed to confirm the test now actually guards the sort: temporarily changed `sort_by_ip`'s body back to the old buggy `results.sort_by(|a, b| a.ip.cmp(&b.ip))`. The test then failed as expected, reporting `left: ["10.0.0.164", "10.0.0.2", "10.0.0.23"]` versus the expected `right: ["10.0.0.2", "10.0.0.23", "10.0.0.164"]`. Restored the correct numeric sort body afterward and reran the test, which passed again. This confirms the test now exercises and would catch a regression in the real sort path, unlike before.
   - Full verification rerun after the change: `cargo test --manifest-path src-tauri/Cargo.toml` (999 passed, 0 failed), `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings` (clean), and `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check` (clean, no diff).
